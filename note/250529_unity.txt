# Assembly definition files (어셈블리 정의파일)
어셈블리가 있는 폴더를 기준으로 스크립트를 나눈다. 해당 구간에서 수정되면 그쪽만 컴파일 하는것.
근데 문제는 다른 어셈블리의 소스를 참조를 하는경우 참조가 안되버리는데
어셈블리가 다른 어셈블리를 참조를 시키게 연결 설정을 해서 가능
근데 순환참조구조는 문제임. 어셈블리끼리 서로 참조하는 경우.  (a->b, b->c, c->a 이러면 안됨)
그래서 최대한 순환참조를 피해가며 코드를 짜야함.
참조 방식을 트리구조로 잘 짜야함.

각 스크립트 파일을 폴더별로 구분해서 넣고 안에 Assembly Definition 파일을 만들어둔다.
참조는  Assembly Definition Refereces 에서 다른 ad파일을 적용

# Nav Mesh Agent
- Agent Type : 우리가 아까 네브메쉬 설정한 타입
- Base Offset : 네브매쉬때문에 바닥에 떠있게 되는 경우 Y축 조절
- Speed : 속도
- Angular Speed : 몸이 회전하는 속도.
- Acceleration : 가속도 (스피드가 40이고 가속도가 8이면 최대속도까지 5초 걸림)
- Stopping Distance : 타겟까지의 도착 거리
- Auto Braking : 목적지가 여러개라면 목적지에 다가갈때마다 감속함

Obstacle Avoidance
- Radius : 방애물이 인식하는 agent의 반지름
- Height : 방애물이 인식하는 agent의 높이
- Quality : 로우폴리인지 하이폴리인지 처리. 정교하게 처리할것인지. (성능차이)
- Priority : 예를들어 좁은길에 다수의 몬스터가 지나가려고하면 병목현상이 발생한다. 그럴때 누가 먼저 갈것인지 우선권. 낮을수록 우선권이 높음.

- Auto Traverse Off Mesh Link : 체크시 메쉬가 끊어져있어도 어느정도 넘어갈수있음
- Auto Repath : 길을 계속 새로 재탐색함.

# 추격
플레이어와의 거리를 재서 플레이어를 쫓아가게 해야함.
매 프레임 거리를 체크하는건 성능낭비.
병렬처리 함수를 특정시간마다 호출해서 거리를 계산하자.
코루틴을 사용

Awake() 라이프사이클의 특징.
스크립트가 비활성화 되어있어도 실행이 되는 무조건 초기화 함수.
대신 코루틴 함수 같은건 호출이 안된다. 객체가 전부 초기화 되어야 호출이 되는데
Awake 는 제일 먼저 호출되기때문에 객체 관련 함수는 못씀.

오브젝트풀 이라는 디자인패턴
미리 오브젝트를 몇개 생성해두고 활성화 했다가 비활성화했다가 함.

OnEnable() 라이프사이클 : 활성화할때마다 호출됨
Start랑 Update 보다 우선순위가 빠름

활성화 될때마다 코루틴 함수를 실행시켜서 상태체크를 한다.
일정시간마다 상태체크 (거리를 계산)

상태를 enum 으로 이런저런 값 세팅하고
거리에 따라 상태를 바꿔줌

이제 상태에 따라 행동을 해주는 코루틴 함수도 생성해서 분기별 처리


%
정적할당 : int 형 변수를 하나 만들어서 10을 할당한다. 객체 초기화시 할당됨.
동적할당 : 프로그램이 실행되는 과정에서 임의의 타이밍에 할당.

함수 내 지역변수는 함수종료시 지워지기때문에 메모리걱정을 그렇게 안해도됨

동적할당으로 만들어진 변수는 프로그램이 돌아가는중에 남아있어야하기때문에 메모리 해제를 안하고 계속 남아있음. 이런게 문제가 되서 메모리 용량을 가득채워 게임이 꺼지는 경우도 있었다.
C#에는 가비지컬렉터가 존재하기때문에 이런문제에서 어느정도 해소됐지만
가비지컬렉터가 언제 돌아가는지 우리는 모름. 따라서 성능상 불안정함.
원칙적으로는 변수를 만들어서 사용할때 가비지컬렉터의 대상이 되지 않게 만드는게 좋음.

% readonly 읽기전용. 더이상 동적할당이 안되고 처음에 할당하고 프로그램종료시 해제
% const 상수.
